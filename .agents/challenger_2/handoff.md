## 2. Logic Chain

1. **Cryptographic Integrity**:
   - `src/config/razorpay.js` uses `crypto.createHmac('sha256', secret)` and `crypto.timingSafeEqual` to verify the HMAC against the payload `${razorpay_order_id}|${razorpay_payment_id}`.
   - Observations 1.1 through 1.5 empirically prove that tampered, forged, empty, or wrong-secret signatures are uniformly rejected with 400 Bad Request, while legitimate signatures succeed.
   - Observation 1.6 proves that replay attacks are handled idempotently without corrupting the state machine.

2. **Role-Based Access Control (RBAC)**:
   - `src/middleware/auth.js` enforces cryptographic JWT verification and sets `req.user`.
   - `src/middleware/adminAuth.js` enforces `req.user.role === 'admin' || req.user.role === 'developer'`.
   - Observations 3.1 and 3.2 empirically prove that all 14 admin endpoints enforce both authentication (401) and role-level authorization (403).
   - Observation 3.5 empirically proves that customer orders are isolated so users cannot snoop on each other's purchases.

3. **File Upload Hardening**:
   - `src/middleware/upload.js` employs a dual-defense mechanism: a strict MIME whitelist (`image/jpeg`, `image/png`, `image/webp`, `image/svg+xml`) rejecting non-image payloads with HTTP 415, and dynamic UUID/timestamp filename generation overriding client-supplied paths.
   - Observations 4.1 through 4.6 confirm that webshells, executables, scripts, HTML files, path traversal attempts, and oversized files are reliably neutralized.

4. **Injection Resistance**:
   - `src/config/database.js` uses SQLite prepared statements (`db.prepare(...).get(...)`, `db.prepare(...).all(...)`, `db.prepare(...).run(...)`) with bound parameters for all data queries.
   - Observations 5.1 through 5.4 confirm that input injection strings are treated strictly as scalar data parameters, preventing SQL structure manipulation.
